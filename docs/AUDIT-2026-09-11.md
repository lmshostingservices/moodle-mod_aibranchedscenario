# Full look-and-feel audit — mod_aibranchedscenario v1.18.2

Ten parallel audits: design system, layout, responsive, accessibility, motion,
copy, teacher experience, theme compatibility, edge cases, competitive position.
Every finding below that is marked **verified** was checked against the source by
hand after the audit returned it.

---

## Tier 1 — bugs that strand a user or break the product

### 1. Resuming an attempt after a republish strands the learner permanently — verified
`classes/external/start_attempt.php:72` builds the manager with
`attempt_manager::for_scenario($scenario)` — the *current* published revision —
even when it is resuming an attempt that was started on an older one.
`start_or_resume()` returns the open attempt untouched, then
`get_node($attempt->currentnode)` looks that node up in the *new* definition.
Regenerated scenarios do not reuse node ids, so it throws `error:unknownnode`.

The player only offers **Resume** when an attempt is open, and Resume always
takes this path. There is no learner-facing "abandon and start again", and
`delete_attempt` needs a teacher capability. The learner is locked out until a
teacher intervenes. Every other entry point (`submit_choice`, `get_debrief`)
already uses `for_attempt()`.

**Fix:** resume with `for_attempt()`; add a recovery path in the player when the
node cannot be found.

### 2. A beat with a character line but no picture freezes with no way forward — verified
`templates/node.mustache:71-100` — the avatar button (`data-action="speak"`) is
the only thing that can set `speechDone = true`, and it lives entirely inside
`{{#hasimage}}`. `playAudio()` sets `speechDone = false` whenever a `speechurl`
exists, then `holdWayOn()` disables `[data-action="continue"], .aibs-continuebtn`.
On a beat node — where Continue is the only control — a missing image means the
button is disabled forever. Happens whenever image generation fails for one scene
but narration succeeded, which is exactly the documented partial-generation case.
Decisions are unaffected: `holdWayOn` does not disable choices.

**Fix:** render the speaker control independent of `hasimage`.

### 3. Audio that fails mid-stream freezes Continue with no message — verified
`amd/src/player.js` — the `Audio` object gets an `ended` listener and a `catch`
on the play promise, but no `error` listener. A connection dropping mid-clip
fires `error`, not `ended`, so `narrationDone` never becomes true and Continue
stays disabled while the control still reports narration as On.

**Fix:** treat `error` like the play rejection — mark done, release, show state.

### 4. Four design tokens are self-referential and therefore dead — verified
`styles.css:58,62-64`:
```css
--aibs-warn: var(--aibs-warn);
--aibs-positive-border: var(--aibs-positive-border);
--aibs-negative-border: var(--aibs-negative-border);
--aibs-negative-strong: var(--aibs-negative-strong);
```
A custom property that references itself is a cycle: guaranteed-invalid, so it
resolves to nothing everywhere it is used. Consumers: the amber warn ring in the
debrief (never amber — the three-way traffic light is really two-way), the strong
and high-risk outcome badges (borderless), the emerald theme's accent border, the
crisis chip, and the error banner (loses its red border *and* its red text).

The comments above these lines describe the refactor that was intended; the
right-hand sides were never filled in. The toast scope at line 568 already has
the correct literal (`#f6c9c5`).

**Fix:** real values — `#b45309`, `#b7ead7`, `#f6c9c5`, `#7a1710`.

### 5. Report page ignores groups entirely — verified
`report.php` queries every attempt for the scenario with no group filter and
never calls `groups_get_activity_group()` or checks
`moodle/site:accessallgroups`, while `lib.php:42-43` declares `FEATURE_GROUPS`
and `FEATURE_GROUPINGS`. On a separate-groups course a teacher restricted to one
group sees every other group's learners and grades. A permissions bug, and one a
technical evaluator will find in minutes.

**Fix:** standard `groups_print_activity_menu()` plus a filtered query.

### 6. Content is silently clipped once the shrink floor is reached
`fitSlide()` stops at `scale > 0.74`; anything still too tall sits in a container
with `overflow: hidden` and no scrollbar. A 900-word situation, or a long
consequence, is cut off mid-sentence with no ellipsis and no affordance. The
learner is never stuck — the buttons are `flex: none` — but they can lose the
teaching content. At 200%+ browser zoom this becomes an accessibility failure
(WCAG 1.4.4 / 1.4.10), and a focused-but-clipped control fails 2.4.11.

**Fix:** when the floor is reached and the body still overflows, let that one
region scroll, or abandon the fixed frame for that render.

## Tier 2 — visibly unfinished

### 7. No dark mode — a light slab on a dark theme
Zero `prefers-color-scheme` or `[data-theme]` rules in the file. On Boost Union's
dark toggle, or Moove/Lambda/Academi dark variants, the page goes dark and the
player stays a hardcoded white rectangle. Needs dark values for `canvas`,
`surface`, `surface-alt`, `border`, `border-soft`, `text`, `muted`, every
`*-soft` / `*-border` pair, the six accent themes, and the duplicated toast
literals at line 559. The token hoisting done in v1.18.0 was the hard part.

### 8. RTL is entirely unhandled
Every accent bar is `border-left` (`.aibs-speech`, `.aibs-consequence` and its
signal variants, `.aibs-journey-item`, four `.aibs-review-*` rules, both lesson
cards). `text-align: left` on `.aibs-choice` and `.aibs-option`. Physical `left`
/ `right` on `.aibs-speaker`, `.aibs-avatar-play`, `.aibs-lesson::before`. The
choice arrow slides via `translateX(-6px)` and its glyph never mirrors. The grid
itself *does* mirror correctly — which makes it worse, because
`border-radius: var(--aibs-radius) 0 0 var(--aibs-radius)` on the scene then
rounds the wrong two corners, leaving a visible broken seam.

**Fix:** logical properties throughout, plus a `[dir="rtl"]` block for the
transform and the corner radius.

### 9. The report screen is not inside the product
`report.php` never wraps its output in `.aibs-player` / `.aibs-shell` — the only
selectors carrying the tokens and the branded card. A teacher goes from the
polished wizard straight to a bare Moodle heading, four unshelled stat pills and
a `generaltable`. It reads as a different, older plugin.

The wizard has the same problem in miniature: player and draft-review use
`.aibs-masthead`, the wizard and report just call `$OUTPUT->heading()`. Three
teacher screens, three different page openings.

### 10. The debrief deck is the one deck that is not frame-locked
`.aibs-brief .aibs-deckslide` gets the fixed frame; `.aibs-debrief .aibs-deckslide`
does not exist anywhere in the file. Identical markup, identical arrows, one
scrolls and one does not.

### 11. The primary CTA is buried behind the whole lesson deck
`templates/player.mustache:313-367` — Begin / Resume / Try again exist only on
the last slide of the opening deck, reachable only by stepping through every
principle. There is no skip. The most important button in the player has the
worst position in it. (That block is also indented back to column 0, a sign it
was patched in rather than composed.)

### 12. Defaults make a trial demo fail
`mod_form.php:123` and `:173` both default to 100 — pass grade and completion
minimum score — with `grademethod` of `highest`. A teacher accepting defaults and
playing their own scenario has to make every optimal choice to pass. They will
read that as broken, not strict.

## Tier 3 — accessibility

| # | SC | Finding |
|---|----|---------|
| 13 | 4.1.3 / 2.4.3 | Every choice triggers three overlapping announcements: the `aria-live="polite"` region being replaced, a forced `focusRegion()` move into it, and `animateRings()` mutating counter text ~25 times over 900ms *inside* that live region. Pick one mechanism. |
| 14 | 4.1.2 / 1.1.1 | The three meters wrap the track in `role="img" aria-label="{{label}}"` with no value — a screen reader hears "Trust, image" right after the visible "Trust", and the number is a separate sibling. Either `aria-hidden` the track or use `role="meter"` with `aria-valuenow` / `aria-valuetext`. |
| 15 | 2.4.3 / 4.1.3 | `wizard.js showStep()` toggles `hidden` and scrolls, but never moves focus and announces nothing. Seven steps, no signal to a non-visual author that anything changed. |
| 16 | 4.1.2 | The avatar's name is announced twice — `aria-label` on the button and a visible, un-hidden `.aibs-speaker-hint` with the identical string. |
| 17 | — | Progress rail items carry no `aria-current="step"`. |

**Already strong, and worth keeping:** contrast passes throughout (muted text
6.0:1, accent 6.3:1, positive/negative on their soft fills 4.9 / 5.75:1); the
`prefers-reduced-motion` work is genuinely thorough and correctly keeps the
spinner turning rather than freezing it; every spoken line has a text equivalent;
autoplay blocking is surfaced as a distinct state instead of silent failure;
choices sit in a real fieldset with a visually-hidden legend; fullscreen uses the
native API so Escape and focus retention come free.

## Tier 4 — motion and interaction

18. **The click-to-consequence gap has no visible feedback.** The spinner region
    sits after `data-region="consequence"` in the DOM, which the scroll lock and
    the fixed frame almost guarantee is off-screen at the moment it shows. Put a
    spinner in the chosen button's letter badge.
19. **`fitSlide()` thrashes layout while the entrance animation starts** — up to
    14 write-then-read cycles inside a double rAF, in the same frame as
    `aibs-rise`. Compute the scale once from `clientHeight / scrollHeight`.
20. **Node → consequence is a hard cut.** `hideRegion()` empties the old region
    synchronously, then awaits the new template. Fade out ~120ms first.
21. **The wizard has no motion at all** — `showStep()` toggles `hidden` and
    nothing else, while the player has a full motion language.
22. **Busy indicators flash** on fast calls — no minimum-show delay.
23. **`:active` is indistinguishable from `:hover`** on buttons and choices.
24. Rings and numbers all fire in lockstep while everything else in the product
    staggers; deck slides replay the same entrance going backwards; scene images
    pop in with no fade; the two "needs a click" pulses use unrelated timings.

## Tier 5 — language

Spelling is clean — no Americanisms, no typos across 640 lines. Tone is confident
and unhedged, and the wizard's benefit copy is genuinely good. Three real issues:

25. **"node" leaks into learner-facing errors** — `error:wrongnode`,
    `error:unknownnode`, `error:sequenceconflict`, `error:unknownchoice`. The
    learner has never seen that word anywhere in the UI.
26. **The same object is a "scene", a "Decision" and a "node"** depending on which
    string you read. Settle it: *scene* for anything a learner or reviewer sees,
    *decision point* for the choice-bearing kind, *node* internal only.
27. **`error:generic`** — "Something went wrong. Please try again." The only
    apologetic, actionless string in the file, and the only "Please".

## Tier 6 — commercial gaps

Ranked by how likely each is to lose a sale:

1. **No xAPI or SCORM export.** BranchTrack and iSpring both lead with it. Attempt
   data lives only in this plugin's tables. `build_journey()` already assembles
   almost exactly xAPI-shaped data.
2. **No visual branch map.** H5P, Storyline, BranchTrack and iSpring all give the
   author a tree or flowchart. This edits node-by-node in text forms.
3. **No cohort analytics.** Four summary numbers and a flat table. Nothing answers
   "which decision splits the cohort" or "what should I reteach".
4. **No CSV export and no sortable columns** — `report.php` hand-builds an
   `html_table` instead of using `table_sql`, so it stands next to the quiz report
   looking unfinished.
5. **No per-scene regeneration.** Once generated, the only AI-assisted repair is
   regenerating the whole scenario. For an AI product this is the ceiling a buyer
   hits second.
6. **Mandatory AI dependency** — manual authoring is explicitly not offered.
7. **Moodle app support unverified.** H5P, the free incumbent, works there.

**Differentiators that exist and are not being sold:** crisis variants (the
scenario gets harder if you make it harder), the pre-publish quality review that
catches dead branches, immutable published revisions so a republish cannot
rug-pull a learner mid-attempt, and see-the-price-before-you-spend costing. Only
the metrics and the principles are currently communicated.

**Honest positioning:** the only Moodle branching-scenario tool that turns an
existing policy or procedure document into a fully authored, narrated,
illustrated, auto-graded scenario in minutes — with a price you see before you
spend it, and a quality check that catches dead branches before a learner does.

## What is already good

Worth saying plainly, because these are the parts that already beat the
competition and should not be touched:

- The **import path**. Line-numbered JSON errors, automatic recovery from code
  fences, preambles and unescaped inner quotes, and a prompt generated from the
  schema so it cannot drift from what the validator accepts.
- The **cost confirmation flow** — price, counts and remaining allowance before a
  credit is spent.
- The **draft quality review** — reads every branch before publish and flags
  choices that lead nowhere different.
- The **admin diagnostics** — explains *why* credentials are not resolving.
- **Backup and restore** — complete, and correctly separates content from user data.
- The **sticky-offset band walk** in `player.js` — a careful solution to a real
  Moodle theming problem.
- The **fixed-frame system** itself: commented with real reasoning, degrades
  cleanly below 900×620, ties type size, gaps and padding to one measured ceiling.
- **Overflow defences** against unbounded generator strings — rare in a Moodle plugin.
- The **colour system**: six themes × four tokens plus a semantic base, named by
  role rather than by hue.
